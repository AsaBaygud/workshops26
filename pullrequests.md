# Suggest a change to a Github repository via a Pull Request 

> Step-by-step from Claude, reviewed by us

### Version 2. Working inside a folder, a few weeks on

A pull request is made by one person, so each week one team member should make it.

1. Fork the repo (or sync an existing fork). Go to https://github.com/CompJCDF/workshops26 and click Fork (top right), then Create fork. This makes your own copy of the whole repository, which is where you'll add your files. You can't add files to the original directly — that's why forking comes first.

Already forked it in a previous week? Don't fork again. Open your existing fork (github.com/your-username/workshops26) and click Sync fork → Update branch first. This pulls in everything that's changed in the original since you forked, so you're working from the latest version. Skipping this can make your pull request include out-of-date files or throw up conflicts.

2. Open the right folder. In your fork (the URL will now start with your username, not CompJCDF), click into this week's folder so you're inside it before adding anything. Check the folder name matches what the workshop asked for.

3. Add your files. Click Add file (top right) and choose:

Upload files — drag your files in from your computer, or
Create new file — type a file straight into the browser.
Give your files clear, unique names so they don't clash with another group's — include your group name, e.g. group-b-notes.md. (Tip: if you use Create new file, you can also put it in a sub-folder by typing the path first, e.g. week3/group-b.md.)

4. Save your changes (commit). Scroll down to Commit changes. Write a short note saying what you added (e.g. "Add Group B week 3 files"), leave the default "Commit directly to the main branch" selected, and click Commit changes. This saves the files into your fork.

5. Open the pull request. Go back to the top of your fork — you'll see a banner or a Contribute button offering Open pull request (GitHub may also show Compare & pull request). Click it, add a sentence or two explaining what you've added, then click Create pull request.

6. Wait for a response. The owner of the repository will review your pull request. They may:

- merge it: your files become part of the real repository 🎉
- comment to ask for a change: add or edit files in your fork again, and the pull request updates automatically
- close it without merging

### Version 1. Working inside a single .md file
A pull request is made by one person, so each week *one* team member should make it.

1. Create a GitHub account
Go to github.com and sign up. It's free. Confirm your email address. Your username is public, so choose one you're happy for others to see.

2. Open the workshop repo. Go to https://github.com/CompJCDF/workshops26 and click on this week's .md file.

3. Click the pencil icon ✏️ (top right of the file). GitHub will say you need your own copy to make changes. Click Fork this repository. This makes a copy under your account, so you can't break the original.

4. Make your edits. Type your changes: for workshops this might just be the addition of a URL. The Preview tab shows how the page will look.

5. Save your changes. Click 'Commit changes', write a short note saying what you changed (e.g. "Add our group's notes"), then click Propose changes.

6. Open the pull request. On the next page, click 'Create pull request'. Add a sentence or two explaining your suggestion, then click 'Create pull request' again.

7. Wait for a response. The owner of the repository will review your pull request. They may:

- merge it: your change becomes part of the real file 🎉
- comment to ask for a change: you can edit the file in your fork again, and the pull request updates automatically
- close it without merging
